# Task: Winner bet: pick who wins the pool, on the leaderboard

## Context

SvelteKit 2 + Svelte 5 (runes) + Drizzle ORM on Cloudflare D1. Prediction-pool app: users pick match outcomes, a leaderboard ranks them by points.

New feature: each logged-in user can place one fun bet on **which player ends up #1 on the leaderboard**. No points awarded — bragging rights only. The validated UI (prototyped on branch `proto/winner-bet-variants`, variant B won) puts the bet **directly on the leaderboard rows**: each still-alive player's row gets a small circle button (◎/◉); your current bet shows a "MY BET 🏆" tag; mathematically eliminated players are faded with an "OUT" tag; a one-line hint above the table explains the feature and shows your current bet.

Rules:
- Available immediately (from day one of the tournament) — NOT gated behind tournament end.
- Only players who can still mathematically win are valid bet targets: `points + sum of stage weights of their picks on fixtures with result === null >= current leader's points` (the same simple "catch a stalled leader" rule — no simultaneous-outcome analysis).
- The bet can be changed or cleared freely UNTIL the Final kicks off. Once the fixture with `stage === 'Final'` has kicked off (`isLocked(kickoff, now)` from `src/lib/lock-time.ts`), bets are frozen: the action rejects changes and the UI hides the buttons, keeping the "MY BET 🏆" tag visible. If no fixture with stage `'Final'` exists, betting is open.

Design outline (follow unless you find a materially better fit with existing patterns):
1. **Schema**: new `winnerBet` table in `src/lib/server/db/schema.ts`: autoincrement `id`, `userId` (references `user.id`, unique index — one bet per user), `pickedUserId` (references `user.id`), `updatedAt` text with ISO default, following the `pick` table's style. Generate the migration with `npx drizzle-kit generate` (creates `drizzle/0008_*.sql` + meta updates).
2. **Pure logic** in `src/lib/winner-bet.ts` (unit-testable, no DB): `maxPossiblePoints`-style eligibility — export `withCanStillWin(entries)` (or equivalent) computing `canStillWin` per entry given `{ points, maxPossible }`, and `isWinnerBetLocked(finalKickoff: string | null, now: Date)` built on `isLocked`.
3. **Repository** `src/lib/server/winner-bet/winner-bet-repository.ts`: `getWinnerBet(db, userId)`, `getAllWinnerBets(db)`, `upsertWinnerBet(db, userId, pickedUserId)`, `deleteWinnerBet(db, userId)` — mirror `pick-repository.ts`.
4. **Load** (`leaderboard/+page.server.ts`): compute per-entry `canStillWin` (reuse the already-fetched fixtures/picks), `myWinnerBet: string | null` for the logged-in user, and `winnerBetLocked: boolean` from the Final fixture's kickoff.
5. **Action** `winnerBet` in `leaderboard/+page.server.ts`: requires login (redirect to `/login?then=/leaderboard` like the home `pick` action does for `/`); form field `pickedUserId` (empty string clears the bet); `fail(400)` on unknown target user, `fail(403)` when locked or when target cannot still win. Re-validate eligibility server-side — never trust the client.
6. **UI**: extend `Standings.svelte` with optional winner-bet props (e.g. `winnerBet?: { eligibleIds: string[]; myBet: string | null; locked: boolean; enabled: boolean }` — default absent so the home page's usage renders exactly as today). When enabled: hint line above the table, ◎ button column on eligible rows (each a `<form method="POST" action="?/winnerBet">` with `use:enhance`), "MY BET 🏆" tag on the bet row, faded rows + "OUT" tag for `canStillWin === false`, buttons hidden when `locked` or when not logged in (tag still shown). Match the existing paper/ink aesthetic via the CSS custom props already used in the file.
