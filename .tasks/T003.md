# Task: Bet reveal: show backers on standings rows once the Final is underway

## Context

SvelteKit 2 + Svelte 5 (runes) + Drizzle on Cloudflare D1. The winner-bet feature just shipped (T002): each logged-in user bets on which player ends up #1 on the leaderboard; bets freeze when the fixture with `stage === 'Final'` kicks off (`winnerBetLocked` in the leaderboard load). Bets live in the `winner_bet` table; repository at `src/lib/server/winner-bet/winner-bet-repository.ts` already exports an unused `getAllWinnerBets(db)`.

New behavior: **once bets are locked, everyone's bets become public**, revealed inline on the leaderboard standings rows. The validated UI (prototyped on branch `proto/bet-reveal-variants`, variant B won) shows, under each player's name, a small 🎫 line listing everyone backing that player (comma-separated names in mono font, the viewer's own name highlighted). The hint line above the table changes to explain: bets are frozen and 🎫 shows who's backing whom.

Privacy rule: **before lock, bets stay private** — the load must NOT expose other users' bets while `winnerBetLocked` is false. Only when locked does the load return the full bet list.

Read these files first:
- `src/routes/leaderboard/+page.server.ts` — load + `winnerBet` action from T002
- `src/lib/components/Standings.svelte` — has optional `winnerBet` props (`WinnerBetOptions`); extend that shape. Home page uses `Standings` without `winnerBet` and in `compact` mode — must render exactly as today.
- `src/routes/leaderboard/+page.svelte` — passes the `winnerBet` prop object
- `src/lib/server/winner-bet/winner-bet-repository.ts`, `src/lib/winner-bet.ts`
- `src/routes/leaderboard/leaderboard.test.ts` — test style, including the mocked `winnerBet` action tests
- On branch `proto/bet-reveal-variants`, `src/routes/leaderboard/ProtoRevealRows.svelte` is the throwaway visual reference (the `.backer-line` / `.backer.me` styling). Rewrite properly into `Standings.svelte`; don't copy wholesale.

Design outline (follow unless a materially better fit exists):
1. **Load** (`leaderboard/+page.server.ts`): when `winnerBetLocked` is true, also fetch `getAllWinnerBets(db)` and return `winnerBets: { bettorId: string; pickedUserId: string }[]` (map from the table's `userId`/`pickedUserId`); when not locked, return `winnerBets: []`. Avoid fetching the table at all when unlocked.
2. **`Standings.svelte`**: add `bets?: { bettorId: string; pickedUserId: string }[]` to `WinnerBetOptions`. When `locked` and bets are non-empty: render under each backed player's name a `🎫` line with the backers' display names (resolve bettor names from `entries` — all bettors are pool users; skip bets whose bettor isn't in `entries`), comma-separated, viewer's own name highlighted (green background chip like the prototype's `.backer.me`). Update the locked hint copy to mention the reveal. Rows keep their existing layout otherwise; no new column.
3. **Page** (`leaderboard/+page.svelte`): pass `bets: data.winnerBets` through the `winnerBet` prop object.
